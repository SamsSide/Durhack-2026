### P3 Best Use of Entire

Entire is the Git forge for agent-human collaboration. From syncing your sessions and prompts to
your Git history, to hosting code and replacing the Pull Request with Trails, Entire are
reimagining code hosting and collaboration for the agent era.

Ready to build faster with AI without burning through tokens or losing context? This challenge is
all about building smarter AI workflows. To qualify, your project should leverage as many of
Entire's core capabilities (Sessions, Graph, and/or Brain) as possible. Your project should lean
on Sessions for context and memory and entire-graph for codebase mapping:

- Sessions (Shared Memory): Save your AI agent sessions as instant checkpoints and push them to
  your team. Teammates or other agents can jump in instantly and pick up right where you left off
  with zero context loss.
- Graph (Codebase Mapping): Generate a visual map of how your codebase fits together. Using
  entire graph search instead of letting agents blindly search files to cut token usage by up to
  71%.
- Brain (Persistent Reasoning): Combine your session data and Graph insights into persistent
  project knowledge. Agents can query past decisions and architectural lessons through the CLI or
  MCP so they don't repeat mistakes or undo working code.
- Trails (Code review): Assign you or a teammate's agent a task via Trail (Entire's issue/PR
  combo primitive), the agent works on it, and then let your agent review the code change: does
  the code change match the intent? Should it merge?

We're looking for teams that use Entire to create seamless human-AI collaboration, maintain clean
code history, and show measurable token efficiency.

**P13 QRT, Tagged: Information Hidden in Plain Sight.** "Graffiti has always been more than
decoration. Tags, symbols, colours and repeated motifs can communicate identity, ownership,
warnings or messages understood only by people who know how to read them. At QRT, we are often
looking to discover hidden realities reflected in markets and trading activity. Your challenge
is to take this idea further by inventing a physical language for hidden digital information.
Build two separate tools: an encoder or encoding scheme that takes a secret three-word phrase
and represents it in the physical world; a decoder that recovers the original three words from a
photograph or short video of the creation. Your encoded creation could be a printed image,
hand-drawn tag, stencil, collage, Play-Doh sculpture, an arrangement of stationary or any other
form of physical object. Printing is one option, but you are encouraged to experiment with
colour, shape, position and the three-dimensional form. The physical artefact must be the only
means of communication between the tools. During judging, you will receive a previously unseen
three-word message and need to produce an encoded object, which will be sent to the decoder.
Your decoder should then reproduce the original message. Your solution must survive the journey
into the physical world, including changes in lighting, camera angle, scale, image quality and
imperfections introduced during construction."

Requirements: the message is three words supplied by the judges; a list of 30,000 valid words is
supplied; the creation must be producible in under 5 minutes; if encoding is done by code it
must run on a separate machine from the decoder, with no internet access; only the physical
artefact may transfer information; the decoder must work without internet or human help; no QR
codes, Data Matrix codes or barcodes; the three words must not appear plainly in the creation.

Judging: accuracy on unseen messages; reliability under real-world creation and photography;
how convincingly the data is concealed in the design; visual quality and originality; technical
creativity of the encoding and decoding; quality of the live demonstration. "The strongest
solutions will not merely decorate an existing barcode. They will invent a communication system
in which the creation itself carries a message."

**P18 Neptune North, "Actors work better together".** "Modern technology often relies on
multiple systems collaborating on a common goal. For example, drones in a light show; robots in
fulfilment centres; or LLMs solving different parts of a large problem. In some situations,
communication between these systems is unreliable or unavailable. When this happens, each actor
needs to be able to operate without receiving instructions from a central hub. We want you to
design an approach to a problem which involves systems working together in a distributed
fashion, even when communications are interrupted." Judging criteria: working towards a common
goal (multiple actors work together to solve a problem); independent decision-making (each actor
decides independently to support the group); resilience when communications fail (actors still
make some progress when they can't communicate); something you're excited about (a problem that
interests you, solved in a way that interests you).
